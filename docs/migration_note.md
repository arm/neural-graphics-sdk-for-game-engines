# Migration from release 1.1.0

This note describes changes since the [public GitHub v1.1.0 release](https://github.com/arm/neural-graphics-sdk-for-game-engines/releases/tag/v1.1.0). It covers breaking source/ABI changes and material changes to documented API behavior. Rebuild the SDK, applications, and custom backends together; the affected public structures and callback tables are not binary-compatible with v1.1.0.

## NSS

- **NSS flags and defaults:** Replace `FFX_API_NSS_CONTEXT_FLAG_HIGH_DYNAMIC_RANGE` / `FFX_NSS_CONTEXT_FLAG_HIGH_DYNAMIC_RANGE` with `*_LOW_DYNAMIC_RANGE`. In the current API, unset selects HDR and set selects LDR; v1.1.0 used the opposite selection. Replace `*_ALLOW_16BIT` with `*_DISABLE_16BIT`: the bit now has the opposite meaning, and FP16 is used by default when the backend reports hardware support. `fp16Supported` reports physical-device support, not whether optional features were enabled on an externally created Vulkan device. Applications using the FP16 default must enable `shaderFloat16` and the required 16-bit storage features (`storageBuffer16BitAccess` and `uniformAndStorageBuffer16BitAccess`) when creating `VkDevice`; set `*_DISABLE_16BIT` to force FP32 when those features are not enabled. Replace `*_PRE_PROCESS_FRAGMENT` and `*_POST_PROCESS_FRAGMENT` with `*_PRE_PROCESS_COMPUTE` and `*_POST_PROCESS_COMPUTE`; unset now selects fragment jobs. Update both flag names and any persisted flag masks. The `QUANTIZED` flag remains unchanged. The NSS sample argument `NSS_USE_FRAGMENT` was renamed to `NSS_USE_COMPUTE` with inverted values: map `NSS_USE_FRAGMENT=0` (compute) to `NSS_USE_COMPUTE=1`, and `NSS_USE_FRAGMENT=1` (fragment) to `NSS_USE_COMPUTE=0`.

- **NSS exposure and dispatch structures:** `exposureTexture` was added to `ffxApiDispatchDescNss` and `FfxNssDispatchDescription`. Set `FFX_API_NSS_CONTEXT_FLAG_EXPOSURE_TEXTURE` or `FFX_NSS_CONTEXT_FLAG_EXPOSURE_TEXTURE` and provide the documented 1x1 resource to use it; otherwise use the scalar exposure value. Recompile callers and zero-initialize updated descriptors.

- **NSS pipeline-stage queries:** `ffxNssGetPipelineStageInfo` and the corresponding public API pipeline-stage query descriptor were removed; use the current compute flags/defaults to select a path rather than the removed queries.

## NFRU

- **NFRU and optical-flow job selection:** The NFRU `*_FRAGMENT` stage flags and `ALL_STAGES_FRAGMENT` were replaced by `*_COMPUTE` flags. In v1.1.0, `ALL_STAGES_COMPUTE` was zero and zero selected compute; now `ALL_STAGES_COMPUTE` is the combined compute mask and zero selects the default fragment path. Old numeric masks can therefore select the opposite path. The default NFRU fragment path requires a graphics-pipeline callback. A compute-only backend must select compute for every selectable stage and use a resolution plan that does not require fixed fragment downsampling.

- **Motion hints now require opt-in:** The public v1.1.0 frame-generation and host Optical Flow APIs had hint-stage selectors but no separate hint-enable flag. The current implementation disables motion hints by default. To retain hint generation, set the new `FFX_API_FG_CONTEXT_FLAG_ENABLE_MV_HINTS` for frame generation or `FFX_OPTICALFLOW_ENABLE_MV_HINTS` for the host Optical Flow API. With hints enabled, an old set `MV_HINTS_FRAGMENT` selector maps to the fragment default (leave the corresponding `MV_HINTS_COMPUTE` selector unset); an old unset fragment selector maps to setting the compute selector. The host selector is named `FFX_OPTICALFLOW_ENABLE_MV_HINTS_COMPUTE`. Enabling only the compute selector does not enable hints.

- **Vulkan path features:** The default fragment warp and preprocess path requires `fragmentStoresAndAtomics` to be physically supported and enabled when creating `VkDevice`. If unsupported, set both `FFX_API_FG_CONTEXT_FLAG_WARP_COMPUTE` and `FFX_API_FG_CONTEXT_FLAG_PRE_PROCESS_COMPUTE`; setting only one still selects a fragment path. Compute NSS postprocess/debug requires physical R11G11B10 storage-image support and enabled `shaderStorageImageExtendedFormats`.

- **Backend capability and Vulkan wrapper layouts:** `FfxDeviceCapabilities` adds `fragmentStoresAndAtomicsSupported` and `r11g11b10StorageImageSupported` in existing padding without changing its size or the offsets of the later fields. Custom backend callbacks must populate both values to describe physical support; a zero-initialized capability structure may now reject an otherwise selectable path. The Vulkan wrapper appends `vkGetPhysicalDeviceFormatProperties` to `VkFunctionTable`; rebuild any downstream code that directly includes or depends on this helper table.

- **NFRU FP16 device features:** NFRU now selects FP16 shader permutations when `fp16Supported` reports physical-device support. Vulkan applications must enable `shaderFloat16`, `storageBuffer16BitAccess`, and `uniformAndStorageBuffer16BitAccess` when creating `VkDevice`; the backend cannot inspect enabled features on an externally created device, and NFRU has no context flag to force FP32.

- **Motion/depth descriptors and coordinate contracts:** `mvDepthSize` was added to `ffxApiCreateContextDescFrameGeneration`, `FfxFrameInterpolationContextDescription`, and `FfxOpticalFlowContextDescription`. Initialize it to the shared motion-vector/depth dimensions; for frame generation and frame interpolation, `{0, 0}` retains the documented render-size default. Frame-generation and frame-interpolation `displaySize`, `renderSize`/`maxRenderSize`, resolved `mvDepthSize`, and derived/aligned NFRU lanes must fit the positive signed 32-bit shader-coordinate range; context creation rejects out-of-range dimensions before resource creation. `mvSimilarityRelativeThreshold` was added to the NFRU prepare descriptors; values `<= 0` use the `0.002` default, while NaN and infinities now return `FFX_ERROR_INVALID_ARGUMENT`. The fallback values for the existing similarity thresholds changed from `0.3` / `1.0` to `0.25` / `0.125`; set explicit values to preserve prior tuning. `jitterOffset` is a render-pixel sample-position offset, opposite in sign to rasterized image displacement; `motionVectorScale` maps vectors to `mvDepthSize` pixels, and NFRU's view-projection matrix must be unjittered. Only one prepared frame may be pending per context; dispatch it before preparing another.

- **Optical Flow dimension validation:** In the host Optical Flow API, `{0, 0}` uses `maxRenderSize` for the depth/motion input size. Partial-zero input dimensions, and `resolution` or `maxRenderSize` dimensions outside the positive signed 32-bit shader-coordinate range, now return `FFX_ERROR_INVALID_ARGUMENT` before lane derivation. When motion hints are enabled, current `depth` must match the input size; previous `depthTm1` must match either the input size or resolved lane. Dispatch rejects mismatches before registering resources or scheduling GPU work. The returned `depthTm1` and `depthTm1Next` shared-resource descriptions use the resolved lane dimensions.

- **Frame-interpolation dispatch structure:** `opticalFlowSceneChangeDetection` was removed from `FfxFrameInterpolationDispatchDescription`. Recompile callers, zero-initialize the updated descriptor, and remove the deleted field from initializers.

- **Frame-interpolation entry points and queries:** Rename `ffxFrameInterpolationDispatchDownsampleColour` to `ffxFrameInterpolationDispatchDownsampleOfColour`, `ffxFrameInterpolationGetRequiresColourDownsample` to `ffxFrameInterpolationGetRequiresOfColourDownsample`, and `ffxFrameInterpolationGetDownsampledColourP1/M1` to `ffxFrameInterpolationGetDownsampledOfColourP1/M1`. `ffxFrameInterpolationGetPipelineStageInfo` and the corresponding public API pipeline-stage query descriptor were removed; use the current compute flags/defaults to select a path rather than the removed queries. `FfxFrameInterpolationPass` values were expanded and renumbered (including removal of `FFX_FRAMEINTERPOLATION_PASS_FILL_HOLES_TP1`); do not persist or exchange their old numeric values. The frame-interpolation version macros changed from `0.1` to `1.0`.

## Common changes

- **Dataset Capture configuration (new after public v1.1.0):** Dataset capture was not part of the public v1.1.0 release. In this unreleased integration, capture is enabled by default. The integration is controlled by `FFX_CAPTURE_ENABLED`; `FFX_CAPTURE_ENABLED=OFF` removes capture support, including programmatic capture descriptors, while `FFX_CAPTURE_ENABLED=ON` retains both the API and runtime environment/property polling. Environment/property polling requires a complete request, including `CONFIG_REVISION`/`revision`, to be published before context creation; use the programmatic API when configuration must be supplied after startup. API BEGIN output directories are limited to 512 bytes and overlong values return `FFX_API_RETURN_ERROR_PARAMETER`. Android capture uses `debug.ngsdk.nss.*` / `debug.ngsdk.nfru.*`, desktop staging uses `NGSDK_CAPTURE_POOL_HOST_VISIBLE_RATIO`, Android staging uses `debug.ngsdk.pool_ratio`, desktop performance uses `NGSDK_CAPTURE_PERFORMANCE`, and Android performance uses `debug.ngsdk.capture.perf`.

- **Shared ABI and backend interfaces:** `FfxApiResourceDescription` no longer has `batchSize` or `shapeSize`. `FfxApiEffectMemoryUsage` and `FfxEffectMemoryUsage` gained `textureUsageInBytes`, `bufferUsageInBytes`, `tensorUsageInBytes`, and `dataGraphUsageInBytes` before `aliasableUsageInBytes`, changing the structure size and field offsets. `FfxInterface` gained `fpGetBackendGpuMemoryUsage`; `FfxBackendMessage` was replaced by `FfxLogMessageCallback(FfxMsgType, const char*)`. The Vulkan `VkFunctionTable` gained `vkCmdClearDepthStencilImage`. `FFX_PI` and `FFX_EPSILON` changed from `const float` objects to macros; callers must not rely on their address or object identity. Rebuild custom backends and update callback signatures, table initialization, structure access, and any serialized layouts.

- **Effect identifiers:** Numeric IDs changed for `FFX_EFFECT_NSS` (22 to 21), `ARM_EFFECT_FRAMEINTERPOLATION` (23 to 22), and `ARM_EFFECT_OPTICALFLOW` (25 to 24). Update stored IDs and recompile consumers that use these enums.

- **C++ configure helper:** The no-context `ffx::Configure(desc...)` overload was removed. Use `ffx::Configure(context, desc...)` for context-scoped configuration; for global descriptors, call `ffxConfigure(nullptr, ...)` directly when that descriptor permits a null context.
